# 独立 QQ 组件与数据隔离

DSWhale 的独立 QQ 连接是可选功能。日常使用的官方 QQ 可以继续保留；DSWhale 不查找其安装位置，不修改入口、注册表或日常账号数据，也不通过进程名结束 QQ。

## Windows：安装独立组件

完成 DSWhale 运行环境准备后，在「QQ 连接」中主动安装独立组件。当前支持官方 **NapCat 4.18.42 Windows Node x64** 包：下载先核对官方发布的 SHA256，再核对包内 703 个不可变程序、依赖和原生库文件。安装只解压到 DSWhale 的用户数据目录，不运行安装器，也不会自动启动或登录。首次准备需要约 125 MB 下载空间和更多解压空间。

也可以选择已经解压的同一官方 Node 包根目录，其中应包含 `node.exe`、`index.js`、`wrapper.node` 和 `napcat/napcat.mjs`。文件经过修改、缺失或多出未审定程序时，DSWhale 会拒绝启动。其他版本与 OneKey 布局需要单独验证，不能用重命名文件绕过。

完成配置后，按「QQ 连接」中的主要按钮启动。页面依次显示对话服务、QQ 登录、消息连接；已在运行的独立 QQ 会被沿用。DSWhale 只运行包内的 `node.exe index.js`，不运行从注册表寻找已安装 QQ 的 `launcher.bat`，也不运行 `KillQQ.bat`。

## 首次登录与连接

首次登录由用户在 NapCat WebUI 手动完成。页面提示需要登录时，打开「QQ 登录面板」；控制台顶部的「QQ 管理口令」可通过系统对话框查看或复制 WebUI 口令，与 AstrBot 的控制台口令不同。WebUI 的访问与认证方式也可参照 [NapCat 官方指南](https://napneko.github.io/config/basic)。登录口令、账号和原始日志不会进入状态卡片或诊断报告，本机私有配置也不要上传。

QQ 登录成功后，按页面提示应用消息连接。DSWhale 只添加或更新名为 `DSWhale`、指向已绑定本机端口的反向 WebSocket 客户端，并保留其他客户端和选项；对运行中组件直接应用配置，无需重新登录。连接令牌仅写入本机私有配置，不通过状态卡片回显。已有单账号 OneBot 配置可以复制到隔离工作目录；原文件保留。

成功确认在线后，DSWhale 会在本机保存机器人账号标识。下次启动通过上游支持的快速登录方式恢复同一账号，沿用原有设备数据与登录票据；没有已确认账号时，仅在历史配置唯一的情况下尝试恢复。多个历史账号无法确定时，打开管理面板手动选择，不会用「接收消息的 QQ 号」猜测机器人账号。托管组件暂不加载额外 NapCat 插件。

## 日常启停与升级

「停止对话服务」仅暂停消息处理，独立 QQ 保持运行；再次启动会沿用它。保存聊天功能设置或应用消息连接也不会重启 QQ。需要单独停止 QQ 时，在「QQ 连接 → 高级设置」操作。退出应用、安装应用更新或恢复备份时，会停止本应用管理的进程；外部服务仍由你自行管理。

升级与重新准备组件会保留固定的 QQ 数据、工作目录和已确认账号。不要为了升级删除这些目录、重新导入旧迁移备份，或重置设备。有效登录通常可以恢复，但票据失效、平台验证或账号异常时仍需本人完成登录。

显示「等待手机确认」时，请查看手机 QQ 的实际提示。这个状态本身不能证明账号受到风控；无需反复刷新二维码或重启组件，也没有适用于所有账号的固定等待时长。

## 为什么独立程序仍需要隔离数据

独立 QQ 程序目录不代表数据目录已经独立。上游 [问题 #2135](https://github.com/NapNeko/NapCatQQ/issues/2135) 记录了 OneKey 内置 QQ 仍使用日常 QQ 数据目录、导致初始化卡住的情况。[4.18.42 发布](https://github.com/NapNeko/NapCatQQ/releases/tag/v4.18.42) 包含 [隔离修复](https://github.com/NapNeko/NapCatQQ/commit/093b3bf4aaab03b5ee2837e6010d13350d780b0b)。

DSWhale 在组件的 `config/.env` 中设置绝对路径 `NAPCAT_QQ_DATA_DIR` 和 `NAPCAT_WORKDIR`，分别指向自己用户数据目录中的 QQ 数据与 NapCat 工作目录，并在启动前复查。这样 QQ 内核数据、NapCat 配置、日志与缓存都有独立位置。其余环境文件注释和选项保留，重复的托管字段会合并；不安全链接或注入额外程序的环境选项会被拒绝。

这些隔离数据包含登录票据，应当按账号凭据保护。重新安装组件不会覆盖已有独立目录。备份或迁移时，只使用本机私有备份功能，并先停止组件。

## Linux 与 macOS

Linux 可以选择已经解压的同版官方 Shell 目录，验证文件后写入隔离设置和 OneBot 连接；启动仍由用户依据官方独立部署指南完成。使用私有容器或独立包时，确保 QQ 数据卷与 NapCat 工作目录独立，并将反向连接指向 DSWhale 的本机监听端口。DSWhale 不执行系统安装脚本，也不更改系统 QQ。

macOS 提供外部协议端连接方式，不进行本机 QQ 注入或入口修改。上游的本机 macOS 安装方法需要修改 QQ 入口，超出 DSWhale 的隔离范围；请使用独立机器或容器部署，再通过受保护的本机隧道连接。DSWhale 不自动创建隧道或开放公网监听。

NapCat 属于第三方协议实现，隔离只能减少数据和运行目录互相影响，不能保证腾讯服务的兼容性、账号可用性或免于风控。请遵循平台规则，只连接自己管理且明确授权的账号。
