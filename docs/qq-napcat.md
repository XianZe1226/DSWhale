# NapCat：第一次使用普通 QQ 小号

此方式把一个普通 QQ 账号接到 AstrBot，适合需要 QQ 签名、QQ 空间等 OneBot 功能的用户。它属于第三方协议接入，独立数据目录只能减少相互影响，不能保证账号免于平台限制。只有一台电脑、优先使用官方接口的用户可选择 [QQ 官方机器人](qq-official.md)。

## 准备账号与应用

1. 为机器人准备一个独立 QQ 账号，与自己的个人 QQ 互加好友。
2. 安装 DSWhale，在「运行环境」完成准备。不要同时启动旧源码目录里的 AstrBot，避免占用同一端口。
3. 打开「QQ 连接」，查看 **普通 QQ 小号** 页签。填写「你的 QQ 号」并保存，填的是**接收消息的个人账号**，不是机器人账号。
4. 点击「启用 QQ 小号连接」，按提示确认。首次保存账号不会自动启用平台；已启用的连接可跳过此步。
5. Windows 使用下节托管组件流程；macOS / Linux 使用后面的外部服务流程。

## Windows：由 DSWhale 管理独立组件

1. 按连接页当前的主要按钮准备独立组件。应用下载并校验受支持的 NapCat 上游发布包，放进自己的目录。
2. 准备完成后点击启动。页面顺序为「对话服务 → QQ 登录 → 消息连接」；已有有效登录会尝试恢复。
3. 首次需要登录时，打开「QQ 登录面板」。用顶部「QQ 管理口令」查看或复制 NapCat WebUI 口令；它不是 AstrBot 密码，也不是 QQ 密码。
4. 在 NapCat 面板扫描**机器人账号**的登录二维码，按手机提示确认。不要把个人大号登录进机器人组件。
5. 返回连接页，按提示「应用消息连接」。应用只维护自己的反向 WebSocket 客户端，保留其他已有客户端，不为修改连接而重启 QQ。
6. 等待显示「QQ 已连接」，然后从个人 QQ 给机器人发送 `/fish whoami` 和一条普通消息。

默认 OneBot 端口为 `6199`，AstrBot 控制台为 `6185`，NapCat 管理页面通常使用 `6099`。高级设置中的令牌要与协议端一致。日常流程以页面当前提示为准，无需逐个点击组件维护按钮。

DSWhale 不替换、注入或卸载日常官方 QQ。组件程序、QQ 设备数据和工作目录独立保存；只结束自己启动的进程。详细边界见 [QQ 隔离说明](qq-isolation.md)。

## macOS / Linux：接入外部 NapCat

DSWhale 不在这两个平台自动注入个人 QQ。按 [NapCat 官方独立部署指南](https://napneko.github.io/guide/boot/Shell)准备协议端，并登录机器人账号。可使用自行维护的独立环境或容器；不想维护协议端时优先选择官方机器人模式。

1. 在 DSWhale 保存个人 QQ 和平台 ID，例如 `dswhale-qq`，启用小号连接，再启动对话服务。
2. 在 NapCat WebUI 对应机器人账号的网络设置中添加 **WebSocket 客户端**，不是 WebSocket 服务端。
3. 若两者位于同一台电脑，填写：

   ```text
   ws://127.0.0.1:6199/ws
   ```

4. 填入 DSWhale 高级设置里相同的 OneBot 令牌，启用并保存。
5. 若协议端位于容器或其他设备，`127.0.0.1` 指向它自己。需自行建立受保护的本机隧道或受控网络映射，不要直接暴露无保护的公网端口。
6. 从个人 QQ 发消息，确认连接与回复。Linux 可选择受支持的官方 Shell 目录写入隔离设置，但协议端仍由自己启动和管理。

## 模型、记忆与功能

1. 在「模型与记忆」添加模型供应商和聊天模型，配置 LivingMemory 与 Embedding。不要为了调整聊天模型而随意更换已有记忆库的向量维度。
2. 私聊发送 `/fish status`，确认主人绑定与功能状态。
3. B站功能需单独登录鱼的 B站账号，见 [B站指南](bilibili.md)。不要把 B站 Cookie 当作 QQ 或模型凭据。
4. 主动互动默认关闭。先设置安静时段、活动间隔、每日预算与未回复上限，再开启。
5. 签名和空间默认关闭。空间需先创建草稿，由主人发送完整确认命令后才发布；开启开关本身不会替你发空间。

## 日常启停与升级

- 「停止对话服务」保留独立 QQ 运行；再次启动会沿用它。
- 退出应用、应用更新或恢复备份会停止本应用管理的进程。重新打开后尝试恢复有效登录。
- 升级保留固定的设备数据、工作目录与已确认机器人账号。不要删除 `napcat/qq-data`、`napcat/work`，不要重复导入旧迁移快照。
- 登录票据失效或平台要求验证时仍需本人确认。显示「等待手机确认」时查看手机 QQ，不要反复刷新二维码或重启；不存在适用于所有账号的固定等待时长。
- 可以与 QQ 官方机器人同时启用：普通小号负责签名、空间等 OneBot 功能，官方连接负责另一路私聊；主动消息只走选定的默认渠道。停用小号需要在「连接管理」输入「小号」确认，取消不会停止进程。

## 排错

| 现象 | 检查方式 |
| --- | --- |
| 只有“配置已保存”，收不到消息 | 保存配置不代表在线。检查机器人登录状态、WebSocket 客户端地址和令牌。 |
| 端口占用 | 关闭自己确认的旧服务，或更换端口并同步协议端。应用不强杀未知进程。 |
| 能收消息但不回复 | 先检查模型供应商、模型选择及余额，再检查主人绑定与权限。 |
| 签名或空间无法操作 | 确认当前是 NapCat 模式、开关已启用且为绑定主人私聊；平台仍可能拒绝相应操作。 |
| 下载失败 | 使用系统网络，需要时开启 Clash 系统代理或 TUN 后重试，无需另配 DSWhale 代理。 |

不要公开账号数据、管理口令、连接令牌、聊天、记忆或整个运行目录。需要反馈时，使用应用内诊断报告，见 [排错指南](troubleshooting.md)。
