# 体检与排错

「运行环境」可以重新体检。「应用设置」可导出诊断报告；首次环境安装失败、尚未准备好 Python 时也可导出。

## 常见提示

| 提示 | 处理方式 |
| --- | --- |
| PKG-001：组件缺失或不完整 | 停止服务，点击修复运行环境。B站桥接等程序文件会重新准备，私人数据保留。 |
| PORT-001：端口被占用 | 检查是否有旧 AstrBot 或其他服务在运行。可手动停止旧服务，或在「连接设置」修改控制台、OneBot 端口；后者需同步 QQ 协议端。应用不会强杀未知进程。 |
| BILI-001：B站桥接未就绪 | 先确认已开启 B站功能并启动服务，稍后重新体检；组件不完整时修复环境。登录与私信状态在 B站页面核对。 |
| NET-001：下载或连接失败 | 检查系统网络；需要代理时，在 Clash 开启系统代理或 TUN，然后重试。DSWhale 无需另填代理端口，也不会修改系统代理。 |
| UPD-001：更新未完成 | 到应用设置查看未完成步骤、修复或回退。不要直接删除更新记录和备份。 |
| NAP-001：独立 QQ 组件未就绪 | 核对官方组件与隔离配置。先启动服务，扫码登录小号，再配置反向连接。 |

## Clash 与下载

DSWhale 沿用操作系统网络设置。Clash 系统代理会用于桌面下载，并传递给环境准备所需的子进程；TUN 模式按系统网络路由工作。应用不要求配置另一套代理或镜像，不会开启、关闭或修改 Clash。

网络设置改变后，重试当前下载或环境准备即可。代理仅在相应进程使用，本机控制台和 QQ 反向连接绕过代理。不要关闭证书校验或跳过下载哈希检查。

## 体检能确认什么

本机体检检查版本、公开组件文件、端口、配置存在性及运行中的连接状态。它不会发送聊天、不调用计费模型，也不会代替你登录 QQ 或 B站。模型实际能否响应、QQ 消息是否往返、记忆能否召回，仍需用自己的账号发测试消息验收。

群聊由 AstrBot 自己的会话管线处理。DSWhale 的主人专属人格、工具和记忆读取仅对绑定的私聊生效；额外记忆插件也应使用合适的会话隔离设置，不要将私人记忆配置成全局共享。

## 诊断报告

导出前会展示内容清单，保存后由你决定是否提供给维护者。报告只有固定的四个文件：

- `health.json`：检查项、通过状态和错误代码。
- `events.json`：有限数量的操作事件代码与时间。
- `versions.json`：组件版本和更新阶段。
- `README.txt`：报告范围说明。

不收集账号、电脑路径、代理地址、配置值、人格、聊天、记忆、密钥、令牌或原始服务日志。应用默认只保留有大小限制的结构化事件，不转发可能包含私人内容的子进程输出。请不要附上整个运行目录或私人备份。
