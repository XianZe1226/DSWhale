# B站养鱼设置

版本 0.2.0a2 保留 dsh-bili-whale 0.4.6（提交 `8b0009f8ce2ebdc421afcb2e727b19ac18912ec6`）的完整工具和原设置页，把原 DSH 唤醒接口接到 AstrBot。上游代码和 MIT 许可证随包保存，修改记录见 [UPSTREAM.md](../dswhale/bili_bridge/UPSTREAM.md)。

## 最短配置路径

1. 先按 README 跑通普通 QQ、聊天模型、图片模型和 LivingMemory；确认主人号向小号私聊 `/fish status` 能收到回复。
2. 在 **AstrBot → 插件 → DSWhale → 配置**开启 `bili_enabled`；需要主动活动时开启 `proactive_enabled`。保留正确的 `owner_qq`、`owner_umo` 和 `vision_provider_id`。安装器已处理 Node 时，`bili_node_path` 留空。
3. 保存配置并重载 DSWhale。若之前暂停过，在主人 QQ 私聊发送 `/fish start`。
4. 双击项目根目录 **Bili-Settings.command（Mac）或 Bili-Settings.cmd（Windows）**。设置页仅在本机开放，端口随启动变化；不要复制或转发带令牌的打开链接。
5. 在养鱼页的登录区扫码，登录**给鲸鱼使用的 B站账号**。优先扫码，不需要把 Cookie 贴进聊天。页面确认登录账号后，再填写以下字段并保存。

| 设置位置 | 填什么 |
| --- | --- |
| 养鱼页「主人」`owner.mid` | **你的 B站主号 UID**；个人空间地址 `space.bilibili.com/123456` 中的数字，不能填 QQ 号 |
| 养鱼页「主人」`owner.name` | 你的 B站昵称，用于核对和称呼 |
| 养鱼页「她自己」`self.mid` / `self.name` | 扫码登录的鲸鱼 B站小号 UID / 昵称；以登录结果为准 |
| 养鱼页「人设」 | 鲸鱼名称、自称、对你的称呼；详细聊天人格在 AstrBot 的 DSWhale `persona` 里 |
| 养鱼页「偏好」 | 喜欢、不喜欢、搜索关键词；先填少量明确兴趣 |
| 养鱼页「作息」 | 至少一个活动窗口、每个窗口唤醒次数；初次验收把「今晚不看的概率」设为 0，验证后恢复 |
| 养鱼页「分享」 | 选择 QQ、B站私信或评论区 @ 中的一种；填写评分门槛、每日上限 |

保存后运行页面「依赖体检」。本机同时需要可用 Node、ffmpeg/ffprobe、有效 B站登录、正确主人信息与 QQ 连接。作息窗口和 DSWhale 的免打扰时间必须有交集以外的可活动时间：默认 B站 20:00–24:00，而 DSWhale 23:00–08:00 免打扰，因此默认实际活动时间只有 20:00–23:00。

## 通过 QQ 给你推荐

- 养鱼页：`share.via = qq`、`share.enabled = true`。
- DSWhale 插件：`bili_qq_recommendations = true`、`proactive_enabled = true`、`bili_enabled = true`。
- `owner_qq` 是**你的 QQ 主号**；`owner_umo` 是该私聊会话通过 `/fish whoami` 得到的完整值。不要手写一个不对应当前平台的会话 ID。
- 无需打开 `bili_allow_dm` 或 `bili_allow_public`。视频推荐只发绑定的主人 QQ，不从外部评论中决定收件人。
- QQ 推荐和普通主动聊天共享每日预算与未回复限制。达到上限时会安静等待；不是设置失效。B站侧还会检查评分和重复 BV。

## 通过 B站私信给你推荐

- B站**主号与鲸鱼小号互相关注**，`owner.mid` 填主号，扫码登录小号。上游私信通道会核对身份与互关，并限制当天收信人。
- 养鱼页选择 `share.via = dm`，开启分享。希望它主动处理你的 B站来信时，再开启 `listen.dm`。
- DSWhale 插件打开 `bili_allow_dm`，这是允许自动 B站私信的开关。关闭时，模型提出的发送请求进入待确认队列；主人 QQ 用 `/fish pending` 看内容，再用 `/fish approve 操作ID` 执行一次。
- B站私信另受上游额度、风控与送达校验约束。接口返回提交成功不等于对方已读；失败和不确定投递不会自动重发。

**接收主人私信和推荐渠道是两件事。** 想保持“视频发 QQ，同时在 B站回复我的私信”，保留 `share.via = qq`，在养鱼设置页「倾听」打开 **私信监听（只认主人）**，即 `listen.dm = true`；DSWhale 中的 **允许自动给 B站 owner.mid 发私信**（`bili_allow_dm`）也要打开。仅打开后一个开关不会收取消息。保存养鱼页后监听设置即时生效。`/fish bili` 可以查看监听开关。

登录正常只证明能登录，不代表监听开启或可发送。私信只识别已绑定主人、要求双方互关；暂停与 DSWhale 安静时段仍会阻止自动处理。监听通常按一分钟轮询，失败会退避，不能保证实时到达。首次开启会处理最近一页尚未确认的主人文字消息，可能包含开启前刚发送的消息，不要反复重发测试。

## 在 QQ 一句话喊她去看

完成 B站登录、主人绑定、图片模型配置并重载新版 DSWhale 后，可以直接私聊：

- “你自己去 B站看个视频吧”
- “去找点 AI 相关的视频看看，回来跟我说说”

普通聊天模型会调用 `dswhale_bili_watch_now`，立刻确认安排，再由现有 B站账号和后台流程选题、读资料、抽帧和写日记。它不依赖可选的 OpenBiliClaw，也不需要主人提供链接。完成后只发一条汇报；满足分享规则的视频链接合并在同一条里，没有合格推荐也会交代结果。证据范围区分实际读取的字幕、评论和抽帧，下载了图片不算已经看过。

喊话、定时任务和链接观看不会同时运行。忙碌时会提示等待；两次喊话至少间隔10分钟。看完汇报占用一次 DSWhale 每日活动预算，失败也计数；推荐链接另受 B站分享额度、评分和重复 BV 规则约束。23:00–08:00 默认安静时段及暂停、未回复限制不会被喊话绕过。任务中断、发送结果不确定不会自动重跑或重发；`/fish status` 和 `/fish journal` 可查最近任务结果。

入口分工：没有链接的自然语言请求走 B站账号后台任务；已有标准链接的 `dswhale_watch_video` / `/fish watch <链接>` 保留原视频读取路径；养鱼页生物钟继续驱动定时活动。抖音仍是标准链接读取，尚不支持主动浏览抖音推荐流。

默认不要开启公开发言。评论、弹幕、动态等自主写操作还需单独开启 `bili_allow_public`，或逐条确认；上游的额度、白名单和 `--dry`/`--go` 约束仍然有效。

## 保留的功能与入口

| 上游能力 | 本版本入口 |
| --- | --- |
| 扫码/手动凭据、账号验证、设置和依赖体检 | 原养鱼设置页；凭据不回显给模型 |
| 随机作息、跳过概率、间隔、会话轮换 | 原调度器 → 持久队列 → AstrBot 工具调用；暂停关闭进程 |
| feed/search、字幕、简介、弹幕热区、热评、封面、九宫格、字幕带 | `bili_command`；图片交给已配置图片模型；失败不能声称看过 |
| 收藏、评分、判重、每日分享额度、沉默衰减 | 原工具规则；QQ 推送另叠加 DSWhale 的同一套预算 |
| 两本日记、反馈校准、评论汇总 | 独立鱼日记；真实 QQ 来信也记为反馈，不写入个人长期记忆 |
| 评论/私信/直播监听、待审回复 | 原监听器与设置页；生成由 AstrBot 完成；写入受授权约束 |
| 评论 @、评论删除、直播弹幕、动态与图文动态、编辑、回读核查 | 原 CLI 全部保留；设置页底部「手动工具」接受 JSON 参数数组 |
| AI 评论抽样保护、流量保护、自检 | 原工具和原测试保留；模型可抽样/提交评估，不能自行放宽策略 |
| 通知后端 | 原设置仍可用；QQ 推荐使用 DSWhale 的绑定主人通道 |

手动工具示例：`["help"]`、`["session"]`、`["quota","status"]`、`["debrief","BV1234567890","--no-frames"]`。最后一个 BV 是占位符，要替换为实际视频。手动工具中的 `--go` 会真实执行，请先运行 `--dry` 并核对目标。文件型图文/编辑命令只供本机手动操作；模型不能任意读取本机文件或执行 shell。长时间监听优先使用原设置页，手动单次工具限时约 200 秒。

这保留的是上游 0.4.6 的功能，不自动追踪其未来版本；不包括 DeepSeek Harness 自身的界面、权限系统和桌面动画。模型能否选择合适内容仍依赖所用模型，不能保证每轮都会推荐。

## 数据位置和故障排查

所有数据位于 `.runtime/astrbot/data/plugin_data/astrbot_plugin_dswhale/bilibili/`，包括 `.bili-ai/credentials.json`、`.dsh/bili-whale.config.json`、两本日记、工具产物、待确认队列和独立活动历史；不要分享整个目录或备份。模型会收到执行任务所需的视频资料与人格，凭据不作为工具结果发送。

`/fish pause` 同时停主动聊天与 B站进程；`/fish start` 恢复。浏览器设置页因暂停失联属正常，恢复后重新双击 Bili-Settings。没有 Node 或 npm 依赖时 B站进程启动失败，普通 QQ 功能仍可使用；关闭 AstrBot 后重跑 Install。

未收到推荐先查：主人绑定 → 登录/互关 → 模型 → 是否暂停 → 免打扰/活动窗口 → 跳过概率 → 当日额度/未回复上限 → 风控提示。不要通过反复重试发送来测试账号。工具产物累计超过 1 GiB 会停止新任务；停宿主后先备份，再手动归档 `.dsh/shots`，不要删除凭据和状态库。

## 追问内容与等待时间

完成推荐后，可直接问“给我介绍介绍刚才那个视频”，普通聊天会读取本机保存的公开视频日记和最近任务报告；`dswhale_bili_notes` 只读本机资料，不再访问 B站，不读取鱼的私密日记。状态里的“已结束”表示任务已完成，不能再误称只有出发回执。

自动阅读优先取字幕、简介和评论；`debrief` 自动禁用隐式抽帧。只有已知时长且不超过插件 `max_video_seconds` 的视频才自动下载抽帧，每条本轮最多尝试一次，一轮最多两条，采用等间隔采样。长视频仍能读取文字资料。手动养鱼工具保留完整上游能力。追问已有笔记通常只需聊天模型回复；新看一轮仍受网络和模型速度影响，没有固定秒数保证。
