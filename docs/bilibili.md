# B站功能

DSWhale 集成 [dsh-bili-whale](https://github.com/Alterssss/dsh-bili-whale) 0.4.6，支持自主选题、视频阅读、日记、推荐和消息监听。上游代码保留 MIT 许可证，适配说明见 [UPSTREAM.md](../dswhale/bili_bridge/UPSTREAM.md)。

## 启用服务

1. 先完成 [基础配置](setup.md)，确认 QQ 私聊、聊天模型和图片模型可用。
2. 在 AstrBot「插件 → DSWhale → 配置」中开启 `bili_enabled`，保存并重载。`bili_node_path` 通常留空，由安装器管理 Node。
3. 桌面用户点击左侧 B站入口，在当前窗口打开设置页面。终端部署可运行根目录的 `Bili-Settings.cmd`（Windows）或 `Bili-Settings.command`（macOS）。
4. 扫码登录机器人使用的 B站账号，填写绑定用户信息、偏好、作息和推荐渠道。
5. 运行页面中的依赖检查，确认登录状态、Node 和 FFmpeg 正常。

设置页仅在本机开放，端口和访问令牌由启动入口生成。服务暂停或重启后，从应用内重新点击 B站入口；终端部署重新运行 Bili-Settings。不要复用旧页面地址。

## 基本设置

| 位置 | 配置 |
| --- | --- |
| 「主人」`owner.mid` | 接收推荐的 B站账号 UID，可在个人空间地址中找到 |
| 「主人」`owner.name` | 对应账号昵称 |
| 「她自己」`self.mid` / `self.name` | 扫码登录的机器人账号，由登录结果确认 |
| 「人设」 | 名称、自称和称呼；完整聊天人格在 DSWhale 的 `persona` 中设置 |
| 「偏好」 | 兴趣、排除项和选题关键词 |
| 「作息」 | 活动窗口、唤醒次数、最短间隔和跳过概率 |
| 「分享」 | 推荐渠道、评分门槛和每日上限 |

B站 UID 与 QQ 号是不同的账号标识。请勿将机器人 UID 填入 `owner.mid`。

## 推荐到 QQ

设置以下选项：

- B站设置页：`share.via = qq`，开启 `share.enabled`。
- DSWhale：开启 `bili_enabled`、`proactive_enabled` 和 `bili_qq_recommendations`。
- `owner_qq`、`owner_umo` 与当前绑定的 QQ 私聊一致。

QQ 推荐无需开启 B站自动私信或公开互动。推荐与主动聊天共享每日活动预算、免打扰时段和未回复上限；视频评分与重复推荐规则另行生效。

## B站私信

### 接收和回复消息

1. 绑定账号与机器人账号在 B站互相关注。
2. 在设置页「倾听」开启「私信监听」，即 `listen.dm`。
3. 在 DSWhale 开启 `bili_allow_dm`，允许自动回复绑定账号。

`listen.dm` 控制收取消息，`bili_allow_dm` 控制自动发送，两者独立。关闭自动发送时，模型提出的发送请求进入待确认队列，可在 QQ 中使用 `/fish pending` 和 `/fish approve <ID>` 处理。

监听通常按分钟轮询，并受暂停、免打扰和平台请求限制影响。首次开启可能处理最近一页中尚未确认的消息。

### 通过私信推荐视频

在满足上述账号和发送条件后，将分享渠道设为 `share.via = dm` 并开启分享。

如果希望“推荐发 QQ，B站来信仍可回复”，保留 `share.via = qq`，同时开启私信监听和自动发送即可。

## 在 QQ 中请求选题

支持直接发送：

```text
去 B站找个科技视频，回来聊聊
找点 AI 相关的视频看看
```

任务会在后台选题、读取资料并保存日记。完成后发送一条摘要，符合推荐条件时附上视频链接。继续询问“这个视频讲了什么”会读取已有笔记。

同一时间仅运行一个视频任务。两次选题请求至少间隔 10 分钟，每次尝试占用一次主动活动预算。使用 `/fish status` 或 `/fish journal` 查看最近任务；暂停、免打扰和每日限额同样适用。

## 视频阅读方式

优先读取简介、字幕和评论。需要分析画面时，对已知时长且未超过 `max_video_seconds` 的视频抽帧；每条视频每轮最多尝试一次，一轮最多两条。长视频仍可读取文字资料。

视频输出区分字幕、评论和画面来源。抽样画面可能遗漏细节，不代表逐帧完整观看。抖音当前仅支持标准链接读取，不支持自主浏览推荐流。

## 公开互动与审批

评论、弹幕、动态等自动写操作默认关闭。需要时开启 `bili_allow_public`，或在 QQ 中逐条确认待执行操作。上游的额度、目标校验和 `--dry` / `--go` 约束仍然适用。

发送结果不确定时不会自动重发，请先在平台确认实际结果。

## 手动工具

设置页底部提供 JSON 参数形式的工具入口，例如：

```json
["help"]
["session"]
["quota", "status"]
["debrief", "BV1234567890", "--no-frames"]
```

示例 BV 需替换为实际视频 ID。带 `--go` 的写操作会真实执行，建议先用 `--dry` 检查目标和内容。

保留的上游能力包括：

- 视频搜索、候选筛选、简介、字幕、热评、弹幕热区、封面和抽帧。
- 收藏、评分、重复检查、分享额度和反馈。
- 视频日记、消息监听、评论汇总与待审回复。
- 评论、私信、直播弹幕、动态和图文动态的手动操作。
- 流量保护、账号检查和依赖诊断。

单次手动命令限时约 200 秒，长时间监听应使用设置页的对应功能。原始读取工具中的 `debrief` 禁用隐式抽帧；画面读取通过受时长和体积限制的视频入口执行。

## 数据与排查

B站数据保存在：

```text
.runtime/astrbot/data/plugin_data/astrbot_plugin_dswhale/bilibili/
```

该目录包含凭据、配置、日记、媒体产物和任务状态。媒体产物累计超过 1 GiB 时会停止新任务；停止宿主并备份后，可归档 `.dsh/shots`。

没有推荐时，依次检查账号绑定、登录与互关、模型、暂停状态、活动窗口、跳过概率、活动额度和平台限制。默认 B站活动窗口为 20:00–24:00，DSWhale 免打扰为 23:00–08:00，因此默认可活动时间是 20:00–23:00。

`/fish pause` 会停止主动活动和 B站服务，`/fish start` 恢复。服务未启动时，重新打开设置页前先检查插件日志或运行安装脚本补齐依赖。
