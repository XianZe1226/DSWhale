# DSWhale 桌面使用指南

DSWhale 把环境准备、服务启停、QQ 连接和常用设置放在同一个窗口。聊天、长期记忆、模型和 B站高级页面也从左侧导航打开。

## 第一次打开

1. 从 [Releases](https://github.com/XianZe1226/DSWhale/releases)下载对应系统与架构的安装包。支持 Windows 10 22H2 / 11 x86_64、macOS 13+ Apple Silicon、Ubuntu 22.04 / 24.04 x86_64 桌面。
2. 安装并打开 DSWhale，在「环境」检查组件，再点击准备。该操作需要网络与至少 6 GB 空间；仅打开应用不会安装依赖或登录账号。
3. 等待 Python 3.12、Node.js 22、FFmpeg / ffprobe、AstrBot 和插件准备完成。兼容工具会优先复用，缺失组件下载到应用自己的运行目录，下载文件按固定版本和摘要校验。
4. 启动服务，在「连接 QQ」填写使用者 QQ、平台 ID、OneBot 端口与令牌。按 [配置指南](setup.md)独立准备 NapCat，并登录机器人账号。
5. 在「聊天与记忆」配置模型服务和长期记忆。控制台要求登录时，可在「设置」或控制台顶部工具栏点击「首次登录口令」，通过系统对话框查看或复制；首次登录后设置自己的密码。已有安装沿用原密码。需要 B站功能时，再进入 B站页面并单独扫码登录。

QQ 和 NapCat 不包含在安装包中，应用不会自动注入、替换或卸载系统 QQ。个人 QQ 与机器人账号的登录分别管理。使用独立机器人账号，并遵守相应平台规则。

## 环境准备与修复

「环境」显示本次实际检测到的版本和缺失项。点击准备或重试后才执行安装；失败时查看该步骤的错误，修复网络、磁盘空间或文件权限后重试。不要同时运行旧式启动脚本和桌面服务。

依赖和模型是两件事：应用准备本地运行环境，聊天、图片理解和 Embedding 模型由你选择的服务提供，不会下载模型权重或整套 CUDA。配置密钥前，请了解服务商计费和数据处理政策。

## 数据保存在哪里

程序文件与个人数据分开保存，应用升级会保留个人数据：

| 系统 | 默认应用数据目录 |
| --- | --- |
| Windows | `%APPDATA%\DSWhale` |
| macOS | `~/Library/Application Support/DSWhale` |
| Linux | `~/.config/DSWhale`，或 `$XDG_CONFIG_HOME/DSWhale` |

应用内「打开数据目录」显示本机实际路径。运行环境位于其中的 `runtime`，包含 AstrBot、插件配置、凭据、聊天、记忆及备份。不要将整个目录发到公开 issue 或云端共享；备份含有密钥且不加密。

旧式源码部署继续使用源码旁的 `.runtime`。桌面应用不会自动扫描或导入旧文件夹；需要保留人格、聊天和记忆时，先停止旧服务并创建 DSWhale ZIP 备份，再准备桌面环境，从「设置」导入。导入前会自动备份当前数据，导入后保持服务停止，供你核对账号、路径与记忆配置。详细步骤见[从 0.2 迁移到桌面应用](upgrading.md#从-02-源码部署迁移到桌面应用)。加密归档需使用对应工具处理后再导入，不要直接覆盖运行中的数据库。

## 更新、退出与签名

本版采用手动更新：先停止服务、备份数据，再安装新版安装包。没有后台自动更新下载。卸载程序默认保留数据，需要彻底删除时请先检查并备份自己的应用数据目录。

0.3 预览版默认 Windows 构建没有可信代码签名，可能显示未知发布者；Mac 构建使用临时签名以支持 Apple Silicon 启动，没有 Developer ID 身份或 Apple 公证。CI 可在配置正式证书时生成有开发者签名的 Mac 构建，但不自动公证；具体以每次发布说明为准。请只从项目 Release 下载并核对 SHA-256，不建议关闭系统整体安全保护。

Linux 推荐 `.deb`，由系统包管理器安装依赖并设置 Chromium 沙箱辅助程序。不要以 root 启动应用，也不要添加 `--no-sandbox`；可选 `.tar.gz` 适合了解系统沙箱配置的用户。

## 隐私与版权

DSWhale 没有遥测上报。账号凭据与本地数据保存在你的电脑，模型请求和平台功能会按你的配置联系相应服务。模型服务可能接收对话上下文、记忆摘要、视频字幕和抽样画面，详情见[安全说明](../SECURITY.md)。

请只处理有权访问的内容，不要公开账号 Cookie、私聊记录或受版权保护的原始视频。开源代码许可不代表获得平台账号、视频或聊天内容的再分发授权。依赖版权与许可证见[第三方声明](../THIRD_PARTY_NOTICES.md)。

## 开发者构建

构建需要 Node.js 22.23.4+、npm、Python 3.12，以及目标系统原生打包工具：

```bash
npm ci
npm test
python -m pytest -q tests/test_desktop_stage.py
npm run desktop
npm run pack
npm run dist
```

`pack` 生成解包后的应用；`dist` 生成当前平台安装包，两者均先从公开源码清单准备后端资源，输出位于 `desktop-dist`。macOS 仅构建 arm64，Windows / Linux 仅构建 x86_64。可用 `DSWHALE_BUILD_PYTHON` 指定构建时的 Python 路径。新后端文件应先加入 Git 清单；暂存器不会把未跟踪的本地脚本、数据库或凭据带入应用。

[原生构建工作流](../.github/workflows/desktop.yml)在对应系统执行测试、构建与 SHA-256 计算，仅上传安装包和校验文件；不会自动发布 Release。Mac 正式签名使用仓库的 `MACOS_CERTIFICATE` 和 `MACOS_CERTIFICATE_PASSWORD` secrets。未配置证书时仅作临时签名，不宣称公证。
